# Initial implementation inventory (2026-11-11)

For subsequent Apple build corrections and actual CI/simulator results, see [first build status](FIRST_BUILD.md). The original findings below describe the initial implementation session.

This is an implemented native read-only vertical slice plus extension/integration foundations. It is not a production-complete implementation of every requested phase. Apple UI targets have not been typechecked or run in Xcode in this Linux session; they require the macOS build gate before use/release.

1. **Reused infrastructure.** Main web application, generated version-2 roster, orphan public data branch, sanitized daily activity contract, static APPS/FLOWS metadata and identity palette, Toronto schedule semantics, and the existing public early-shift feed. Existing scripts, Firebase web configuration, web themes, branch publisher, and web CI were preserved.
2. **Native implementation.** SwiftUI dashboard; dynamic bot directory with text/department/role/status/favourite filters; profiles; expandable reporting tree; pan/zoom/selectable static relationship map; group membership; directed daily communication chart and activity text/bot/topic/date filters; automation details and next-run calculations; health/usage availability screens; SwiftData snapshots, shift cache, preferences; honest error/staleness/offline handling; light/dark/system and accents; custom crew:// routes with cold-start bot-route deferral.
3. **Branch/files.** Local branch `feature/native-crew-ios`. Added `ios/` and `.github/workflows/native-ios.yml`. `CrewCore` is a local Swift package with test fixtures. `Crew` contains the app, SwiftData store, views, intents, Keychain, event/Live Activity helpers, and Head Quarter adapter. `Shared` contains App Group snapshot IO and ActivityKit attributes. `CrewWidgets` contains configurable Home/Lock Screen widgets and Live Activity/Dynamic Island UI. `CrewWatch` contains the optional companion. `project.yml` declares app/extension/watch targets with XcodeGen. Documentation is under `ios/docs/`.
4. **Verified working here.** CrewCore compiled with official Swift 6.0.3 on Linux. Ten XCTest cases passed, including actual HTTPS fetching/decoding of current roster, activity, and schedule feeds. Deterministic coverage includes populated and empty activities, daily/weekly/monthly schedules, DST changes, briefing shifts/fallback, cache roundtrip/unsupported schema, stale snapshots, health rules, routes, and network failures. Apple source syntax parsing succeeded. Native UI behavior, SwiftData runtime, intents, widgets, Watch, Keychain, notifications, and ActivityKit remain unverified on Apple platforms.

Current controls explicitly disclose their absence. There is no guessed endpoint or browser bypass.
